Project Purpose

This project documents a sanitized small-business network design using FortiGate firewall security, Cisco Catalyst 9300 switch stacks, segmented VLANs, Windows Server infrastructure, Hyper-V services, Microsoft 365 integration, physical security systems, and monitoring devices.

Design Goals

  • Show a clear separation between user, server, wireless, camera, NVR, management, and specialty device networks
  • Demonstrate how VLANs improve security, performance, and operational troubleshooting
  • Document the logical relationship between firewall, switching, servers, cloud services, and physical security systems
  • Provide a portfolio-safe diagram with IP addressing intentionally omitted

High-Level Topology

The design places the FortiGate 100F firewall at the network edge between the Internet/WAN and the internal switching environment. Three switch cabinets are represented as Cisco Catalyst 9300 switch stacks, with each cabinet containing four switches functioning as one logical stack. Core infrastructure, servers, cameras, access-control systems, wireless access points, workstations, and monitoring devices connect through the switching layer.

  • Approximately 120 Snom 720 IP phones connected through PoE

  • Voice endpoints treated as business-critical infrastructure

  • Assisted with VoIP phone connectivity troubleshooting

  • Helped identify whether issues were related to phone hardware, cabling, PoE, switch ports, or network access

Corrected Network Scope

The VoIP phone environment is documented as a separate voice network. The Snom 720 phones connect to the Ubiquiti EdgeSwitch PoE switching environment and do not pass through the Cisco Catalyst 9300 network. This distinction is important because it accurately represents how voice traffic is separated from the main data switching environment.

Operational Importance

VoIP systems are business-critical because phone outages directly affect communication, support, safety, and daily operations. Supporting a 120-phone deployment demonstrates experience with endpoint scale, PoE infrastructure, physical cabling, and production troubleshooting.

VoIP Administration Portal

The VoIP environment also includes a browser-based administrative portal used to manage users, departments, auto-attendants, hunt groups, call pickup groups, extensions, and related voice-service settings. For public portfolio use, all user-specific entries, telephone numbers, extensions, and organizational identifiers are blurred.

Logical Network Design

A corrected sanitized logical network diagram was created to document the VoIP environment as its own separate voice network. The VoIP phones connect through three Ubiquiti EdgeSwitch PoE switches and do not pass through the Cisco Catalyst 9300 network. The diagram shows the hosted voice/admin portal relationship, firewall/voice-network boundary, PoE switching, and approximately 120 Snom 720 IP phones.

Voice Platform Functions

  • User and department management
  • Auto-attendant and call-routing configuration
  • Hunt groups and call pickup groups
  • Extension assignment and endpoint administration
  • Music on hold and related voice-service settings

Recommended Troubleshooting Workflow

  1. Verify whether the phone powers on from PoE.
  2. Check Ethernet patching from desk jack to patch panel to switch port.
  3. Confirm switch port link status and PoE delivery.
  4. Test with a known-good cable or known-good phone when needed.
  5. Confirm the phone reaches the separate voice network or phone system.
  6. Document the affected port, location, device, and resolution.

Project Documentation

AWS Cloud Infrastructure Lab Documentation

Project Purpose

This lab documents a cloud infrastructure project completed using Amazon Web Services. The goal was to demonstrate fundamental cloud engineering skills by designing a secure, segmented, and monitored AWS environment while also considering cost and cleanup.

Cloud Platform Selection

AWS was selected because it provides commonly used industry services for compute, storage, networking, security, and monitoring. The project focused heavily on VPC networking because it demonstrates important cloud design principles such as segmentation, routing, internet access, and private resource isolation.

Environment Built

  • Account Security: MFA was enabled to strengthen account authentication.
  • S3 Static Website: A static website was hosted using Amazon S3 static website hosting.
  • VPC Design: A VPC was created with public and private subnet concepts.
  • Public Subnet: Public-facing resources were placed in a subnet with Internet Gateway routing.
  • Private Subnet: Private resources were isolated from direct internet access.
  • EC2 Instances: Public and private virtual machines were deployed to test workload placement.
  • Routing: Route tables and Internet Gateway configuration were used to control network access.
  • VPC Peering: Peering was configured between separate VPCs using non-overlapping address spaces.
  • Monitoring: Amazon CloudWatch was used to monitor CPU utilization with an alarm threshold.
  • Cost Review: AWS Pricing Calculator was used to estimate service costs.
  • Cleanup: EC2, VPC, S3, and monitoring resources were removed after the project.

Connectivity Testing

Connectivity testing was performed to validate the design. The public instance was tested for internet access, while the private instance was tested to confirm that it did not have direct internet access. Internal connectivity between instances was also tested to verify routing behavior and private communication.

Monitoring and Cost Control

A CloudWatch alarm was configured to monitor high CPU utilization on an EC2 instance, using a threshold-based alerting approach. Cost estimation was reviewed using AWS Pricing Calculator, and resources were cleaned up after the lab to prevent ongoing charges.
